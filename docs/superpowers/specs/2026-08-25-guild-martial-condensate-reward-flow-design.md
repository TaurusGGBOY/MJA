# 帮会征讨、武学研习与消耗凝晶流程修复设计

日期：2026-08-25

## 目标

在不引入新的业务状态模型、不自动操作登录或付费流程的前提下，完成以下三项改动：

1. 帮会活动征讨在“今日剩余征讨次数 0/2”时领取可领取的击破奖励与征讨奖励。
2. 武学研习检查三个研习框，只点击模板明确匹配“成功”的框，并领取可领取的馈赠奖励。
3. 消耗凝晶在偃武、云州两个地区都通过凝晶钱币图标模板定位购买入口，避免金额 OCR 受图标字符干扰。

所有实机输入继续由 MFW/MaaFramework 发出；每个任务的成功和失败路径最终都必须回到游戏主页。

## 已有证据

- 2026-08-25 的实机截图显示武学研习页面共有三个框：左框为“成功”，中框研习中，右框为空。左框“成功”图样与现有模板 `daily/MARTIAL_STUDY_BREAKTHROUGH_DAILY/success.png` 一致。
- 2026-08-22 的消耗凝晶失败日志显示：偃武购买完成并切换云州后，云州页面模板成功命中，但金额区域 OCR 得到“商876两169文”，未满足金额规则，最终在 `1264-消耗凝结体-选择-云州-之后-购买` 超时并进入原生失败节点。
- 仓库已有两个凝晶钱币图标模板：`condensate_icon.png` 与 `condensate_icon_live.png`，分别覆盖界面中可能出现的两种图标颜色。
- `guild_activity_challenge_daily.json` 和对应测试当前已有用户未提交改动；实现时必须在这些改动之上做增量编辑，不能覆盖或回退。

## 方案选择

采用页面限定、目标限定的识别链：先确认所在页面，再在目标控件的局部 ROI 内识别模板或红点，最后通过 `GuardedInput` 点击命中的识别框。

不采用全屏通用红点检测，因为同一页面可能同时存在多个无关红点；不采用裸固定坐标，因为它不能证明目标当前可领取。只有实机截图证明现有模板不足时才新增模板，并确保模板不含账号信息。

## 帮会活动征讨流程

入口和战斗循环保持不变。在 `0570-帮派活动挑战-帮派-剩余-耗尽` 命中后、关闭活动页之前插入有界奖励收尾链：

1. 在帮会征讨页面的“击破奖励”控件右上角局部 ROI 检查红点。
2. 红点存在时点击“击破奖励”，领取当前可领取奖励并关闭领取结果；红点不存在时直接继续。
3. 回到征讨页面后，在“征讨奖励”控件右上角局部 ROI 检查红点。
4. 红点存在时点击“征讨奖励”，进入奖励页后确认奖励页身份，再点击第一排宝箱。
5. 等待领取结果，点击明确的空白关闭区域，返回征讨页面。
6. 执行现有关闭活动页、关闭帮会页、关闭功能面板和主页边界链。

红点识别必须同时包含页面身份和局部红点证据；无红点是允许分支，不得因为没有奖励而把业务任务记为失败。每个领取动作 `max_hit` 有界且 `retry_times` 为 0，避免重复领取副作用。

## 武学研习流程

保持现有入口和页面身份识别。将当前基于 OCR、只覆盖左侧区域的成功卡片识别替换为三个独立模板节点：

- 左框：在左框 ROI 内匹配 `daily/MARTIAL_STUDY_BREAKTHROUGH_DAILY/success.png`；
- 中框：在中框 ROI 内匹配同一模板；
- 右框：在右框 ROI 内匹配同一模板。

三个节点按左、中、右顺序加入领取循环。只有某个 ROI 内模板命中，才把该模板命中框作为 `GuardedInput` 的点击目标；研习中、空框或其他状态均不点击。每次领取后识别领取结果并点击空白关闭，然后重新扫描三个框，最多领取三次。

三个框都没有成功模板后，进入馈赠奖励收尾链：

1. 在武学研习页面的“馈赠奖励”控件右上角局部 ROI 检查红点。
2. 红点不存在时关闭武学研习页面并回主页。
3. 红点存在时点击“馈赠奖励”，确认奖励页身份，点击第一排宝箱。
4. 等待领取结果，点击明确的空白关闭区域，返回武学研习页面。
5. 关闭武学研习页面并走公共主页边界。

馈赠奖励领取同样只允许一次无重放动作；如果领取后红点消失，即视为收尾完成。

## 消耗凝晶流程

保留现有购买预算、最大数量、购买确认和失败终态，不改变业务控制流。仅替换两个购买入口识别节点：

- `1294-消耗凝结体-凝结体-偃武-货币-入口`
- `1304-消耗凝结体-凝结体-云州-货币-入口`

两个节点都使用模板识别，在各自金额左侧图标的局部 ROI 内匹配 `condensate_icon.png` 和 `condensate_icon_live.png`。实现时根据新鲜实机截图选择 `TemplateMatch` 的模板列表和最低可靠阈值，点击目标取模板命中框，不再依赖金额 OCR 文本，也不点击金额数字区域。

页面身份仍由偃武/云州页面模板提供，动作必须同时满足“正确地区页面 + 凝晶图标模板”两个条件。若两个模板都未命中，沿现有失败链收敛，不通过放宽为全屏坐标来绕过识别。

## 实机观察与截图

实现领取链前，使用当前源码构建新鲜不可变候选，仅运行 `GAME_START` 加目标任务。每次进入新的奖励页面后保存只读截图，用于确定局部 ROI、按钮身份和返回状态；所有点击仍由候选中的 MFW pipeline 执行。

至少保留以下截图：武学三框领取前、每个实际命中的成功框、馈赠奖励页（若红点存在）、帮会 0/2 页面、击破奖励页（若红点存在）、征讨奖励页及第一排宝箱、消耗凝晶两个地区的钱币图标、三个任务最终主页校验。

## 错误处理与状态

- 没有红点或没有成功模板是允许状态，走正常收尾，不记录业务失败。
- 页面身份存在但目标模板长期未命中时，保留当前原生失败契约，并用新鲜截图、识别结果和节点日志定位，不新增第二套结果文件或枚举。
- 领取结果弹窗必须被明确识别并关闭；不得连续盲点多个坐标。
- 每条成功与失败路径都先关闭当前页面并通过公共主页边界，再产生最终原生终态。

## 测试与验收

先补会失败的聚焦测试，再实现：

1. 武学测试断言存在三个使用 `success.png` 的独立 ROI 节点，领取循环只从这三个模板节点产生点击，且最大领取次数为 3。
2. 武学馈赠奖励测试断言红点是可选分支、宝箱点击有页面身份保护、领取动作无副作用重放，并能回主页。
3. 帮会测试断言 0/2 后按“击破奖励 → 征讨奖励 → 第一排宝箱 → 返回”收尾；无红点也能正常结束。
4. 消耗凝晶测试断言偃武与云州的入口均为凝晶图标模板识别，不再包含金额 OCR 规则，并保持页面与目标同帧证据。
5. 运行相关任务测试、资源引用和 JSON 校验。
6. 使用全新候选分别实机运行三个任务；只接受新鲜 `Tasker.Task.Succeeded`、验收结果通过且最终主页截图验证成功。

如果当前账号当轮奖励已被领取，实机验收可以证明“无红点安全跳过”与回主页，但需要保留本轮领取前截图作为红点领取分支的现场证据；不能伪造重复领取结果。
